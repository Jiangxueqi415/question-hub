## 1. 背景与问题

高校课程作业、科创训练和社团调研中，问卷“发不出、收不够、样本同质”是普遍问题。学生常见的替代做法是熟人互填、群发红包或付费代填，带来三个后果：

1. **样本质量差**：同一小圈子互填、敷衍作答、直线作答；
2. **学术诚信风险**：代填、伪造样本、来源不可追溯；
3. **互助不可持续**：靠人情一次性消耗，没有正向激励和信用约束。

本产品把“帮别人填问卷”变成可积累的积分与信誉行为：**先帮助别人，再发布自己的问卷**；同时用服务端计时、漏答率、直线作答、开放题有效性等规则，对低质量作答做基础拦截。

### 1.1 产品定位

面向高校课程调研场景的**校内问卷互助与质量辅助工具**，不是通用问卷平台，也不替代问卷星、腾讯问卷等专业调研工具。

### 1.2 设计原则

- **先给予，后获取**：新用户初始 0 积分，必须先完成他人问卷才能发布；
- **双账本**：积分负责“能不能发布”，信誉负责“愿不愿意认真答”；
- **服务端说了算**：身份、计时、判重、结算、质量判定全部在服务端；
- **不采集敏感信息**：不采集真实姓名、手机号、IP；学号只存加盐 HMAC；
- **可解释**：每一次加分、扣分都有时间、原因、余额，用户可查。

## 2. 目标与成功指标

### 2.1 MVP 目标

一周内交付一个可在微信开发者工具/真机演示的闭环：

> 登录并绑定学号 → 首页看问卷 → 发布一份问卷 → 另一个账号作答 → 服务端质量核验 → 领取 +5 积分/+5 信誉 → 个人中心查看双流水 → 重复领取被拦截。

### 2.2 成功指标（MVP 验收，不虚构实测数据）

| 指标 | 目标 |
|---|---|
| 主流程完成率 | 5 名内部测试用户中至少 4 人无协助完成“发布→作答→领取” |
| 重复领取 | 0 次重复加分 |
| 发布者自填 | 0 次成功 |
| 质量核验 | 3 秒内提交、漏答 >20%、直线作答、开放题无效四类用例均可复现 |
| 接口性能 | 本地/局域网环境，核心接口 P95 < 500ms |
| 稳定性 | 演示流程 10 次连续执行，0 次崩溃、0 次脏数据 |
| 材料完整 | 申报书、PDF、截图、视频、源码、说明齐全 |

> 不在 MVP 阶段宣称“60 人实测”“有效率提升”“满意度”等未经试验的数据。

## 3. 用户与角色

### 3.1 目标用户

- **发布者**：需要完成课程作业/调研的学生，有问卷要回收；
- **填写者**：愿意用几分钟帮助同学、同时积累积分的学生；
- 同一用户既是发布者也是填写者。

### 3.2 角色与权限

| 角色 | 权限 |
|---|---|
| 未登录用户 | 只能看到登录页 |
| 已登录未绑定学号 | 可浏览，不能发布/作答/领取 |
| 已绑定学生 | 浏览、作答、领取、发布、查看个人中心 |
| 发布者（本人问卷） | 查看统计（P1）、编辑/下架（P1）；**不能作答自己的问卷** |
| 管理员 | MVP 不做后台；P1 再考虑 |

### 3.3 典型场景

1. 课程作业需要 30 份问卷，发布者用 10 积分发布，设置截止时间；
2. 同学在首页看到问卷，作答 4 题，领取 5 积分/5 信誉；
3. 发布者在个人中心/统计页看到回收数量与选项分布；
4. 有人 2 秒点完提交，被质量核验拦截，不计分；
5. 有人领了问卷但到期没交，扣 20 信誉，不能再次作答。

## 4. 产品范围

### 4.1 P0（MVP 必须）

| 模块 | 需求 |
|---|---|
| 登录/身份 | 微信登录；绑定学号；学号 HMAC；昵称 |
| 首页 | 待填写问卷列表；积分/信誉双卡；新人任务；空态 |
| 问卷详情 | 题目/选项、截止时间、作答计时、提交按钮状态 |
| 作答 | 单选/多选/开放题；允许未答提交（二次确认）；提交后不可改 |
| 发布 | 标题、分类、耗时、开始/截止时间、题目与选项；双门槛校验；扣 10 积分 |
| 质量核验 | 总时长、漏答率、直线作答、开放题无效；命中 ≥2 判无效 |
| 积分/信誉 | 初始 0；新人 +40 信誉；有效作答 +5/+5；发布 -10；未答完 -5；逾期 -20 |
| 防重复 | 同一问卷同一用户只能提交一次；发布者不能自填 |
| 个人中心 | 昵称、双分、信誉/积分流水、我发布的、我填写的、查看作答 |
| 数据 | 服务端存储；流水可追溯；不存明文敏感信息 |

### 4.2 P1（有余力再做）

- 发布者统计：回收数、选项分布、开放题原文；
- 模板：仲景文化、南水北调、校园服务；
- 封面图上传；
- CSV/JSON 导出（服务端生成，小程序内打开文档）；
- 编辑/下架问卷（有答卷后禁止改题，避免历史答案错位）；
- 举报/下架审核。

### 4.3 明确不做

- 排行榜、积分商城、消息推送、复杂图表；
- 跨设备“绝对一人一卷”（只能 HMAC + 唯一索引，不能宣称绝对）；
- 离线可用（小程序依赖网络）；
- 通用问卷平台能力（逻辑跳转、配额、抽奖等）；
- 管理后台（P1 以后）。

## 5. 核心流程

### 5.1 新用户首次进入

1. 进入小程序 → 微信授权登录；
2. 未绑定学号 → 输入学号 + 昵称；
3. 服务端计算 `studentHash = HMAC_SHA256(salt, studentNo)`，查重；
4. 绑定成功 → 进入首页，积分 0、信誉 0；
5. 首页展示“新人任务：阅读互助规则 +40 信誉”。

### 5.2 发布问卷

1. 首页点“发布问卷”；
2. 校验：积分 ≥10、信誉 ≥40；
3. 填写标题、分类、预计耗时、开始/截止时间；
4. 添加 1–10 题，每题 2–6 个选项（开放题 0 选项）；
5. 提交 → 服务端事务：写问卷 → 扣 10 积分 → 写积分流水；
6. 任一步失败回滚；成功回首页，自己的问卷显示“查看作答统计”。

### 5.3 作答与领取

1. 首页点问卷 → 详情；
2. 服务端创建 attempt，记录 `startedAt`；
3. 用户作答，前端显示计时；
4. 提交时若有未答 → 二次确认“还有 N 题未答，确定提交？”；
5. 服务端校验：截止时间、是否本人发布、是否已提交、attempt 是否有效；
6. 质量核验 → 有效/无效/未答完/逾期；
7. 有效：+5 积分、+5 信誉、写双流水、写作答记录；
8. 返回结果页/详情，按钮变为“已完成填写”，不可重复领取。

### 5.4 个人中心

1. 查看积分、信誉、等级；
2. 查看信誉流水、积分流水（时间、原因、变动、余额）；
3. 查看我发布的问卷（P1 统计）；
4. 查看我填写的问卷 → 点“查看作答” → 高亮原选项、只读；
5. 修改昵称（默认“校园用户”，最多 20 字）。

## 6. 功能需求

### 6.1 登录与身份（P0）

**流程**

1. 小程序调用 `wx.login` 获取 code；
2. 后端用 code 换 `openid`（`jscode2session`）；
3. 未绑定：要求输入学号 + 昵称；
4. 后端校验学号格式（如 10–12 位数字），计算 HMAC，唯一索引查重；
5. 绑定成功写入 `users`，返回 JWT。

**规则**

- 一个 openid 只能绑定一个学号；一个 `studentHash` 只能绑定一个账号；
- 不存明文 `studentNo`，只存 HMAC；盐值放服务端环境变量；
- 昵称默认“校园用户”，2–20 字，过滤空白/控制字符；
- 不做真实姓名、手机号、IP 采集；
- 开发环境提供 `mockLogin` 开关，避免 AppID/secret 阻塞前端联调。

**异常**

- 学号已被绑定：提示“该学号已绑定其他微信，请联系管理员”；
- 学号格式错误：就地提示；
- code 失效：重新登录。

### 6.2 首页（P0）

**内容**

- 顶部：产品名、当前积分；
- 双卡：我的积分（完成 +5 / 发布 -10）、我的信誉分（等级 + 进度条 + 查看记录）；
- 新人任务：未领取显示“阅读互助规则 +40 信誉”；已领取显示“查看记录”；
- 待填写列表：只展示未提交、未过期、非本人发布的问卷；
- 空态：全部完成显示“待填写的问卷都完成了”，提供“去个人中心/去发布”；
- 底部导航：首页 / 发布 / 我的。

**列表字段**

标题、发布者昵称、预计耗时、题目数、截止时间、奖励 +5 积分。

**规则**

- 首页不展示已完成/已过期问卷，只在底部汇总“已完成 N 份，X 份已过期 · 去个人中心查看”；
- 已领取但未答完的记录不计入“已完成”，单独提示；
- 点击自己的问卷进入统计页，不进入作答页。

### 6.3 问卷详情与作答（P0）

**展示**

- 标题、发布者昵称、预计耗时、题目数、截止时间；
- 作答计时：“正在记录作答时间：N 秒”；
- 题目：单选/多选/开放题；开放题 textarea，最多 100 字；
- 提交按钮状态：
  - 0 题作答：灰色“请先作答”；
  - 部分作答：绿色“提交问卷（还差 N 题）”；
  - 全部作答：绿色“提交问卷并领取积分”；
  - 已提交/已过期/未答完：灰色不可点，文案对应状态。

**规则**

- 计时以服务端 `startedAt` 为准，刷新不能重置；
- 截止时间后禁止提交；
- 发布者不能作答自己的问卷；
- 提交后作答不可修改；
- 未答完可提交，但必须二次确认；
- 重复提交返回第一次结果，不重复加分。

### 6.4 发布问卷（P0）

**字段**

| 字段 | 规则 |
|---|---|
| 标题 | 必填，2–40 字 |
| 分类 | 学习调研/生活服务/社团活动/其他 |
| 预计耗时 | 1–60 分钟，默认 3 |
| 开始时间 | 默认当前时间 |
| 截止时间 | 必须晚于开始时间，且晚于当前时间 |
| 题目 | 1–10 题；题干 1–100 字 |
| 题型 | 单选/多选/开放题 |
| 选项 | 单选/多选 2–6 个，非空、不重复；开放题无选项 |
| 发布者 | 显示昵称，不允许填写真实姓名 |

**发布校验**

1. 信誉 ≥40，否则 `CREDIT_NOT_ENOUGH`；
2. 积分 ≥10，否则 `POINTS_NOT_ENOUGH`；
3. 字段校验通过；
4. 事务：写问卷 → 扣 10 积分 → 写流水；
5. 失败回滚，不产生“半份问卷”。

**防连点**

- 提交按钮进入 loading/disabled；
- 服务端用 `requestId` 幂等，重复请求返回同一结果。

### 6.5 质量核验（P0）

服务端在提交时计算，前端只展示结果。

| 标记 | 规则 | 说明 |
|---|---|---|
| `miss` | 未答题数 / 总题数 > 20% | 未答完 |
| `fast` | 总作答时长 < 3 秒 | 明显异常 |
| `straight` | 选择题同选项占比 ≥80%，且选择题 ≥2 道 | 直线作答 |
| `open_invalid` | 开放题去空格后 <4 字，或同字符 ≥80% | 开放题无效；白名单：无/没有/暂无 |

**判定**

1. 未答率 >20%：`incomplete`，不发积分，信誉 -5，记录可查看，不可重答；
2. 否则计算 flags：
   - flags ≥2：`invalid`，不发积分/信誉，不可重答；
   - flags = 1：仍可有效，但记录标记该风险（用于统计）；
   - flags = 0：有效，+5/+5。
3. 超过截止时间且未提交：`expired`，信誉 -20（每份一次），不发积分。

> 规则目标不是“学术审判”，而是拦截明显异常；阈值可在 P1 用真实数据校准，但 MVP 先固定，保证可解释、可复现。

### 6.6 积分与信誉（P0）

**积分（points）**

| 行为 | 变动 | 说明 |
|---|---|---|
| 初始 | 0 | 新用户 |
| 有效完成他人问卷 | +5 | 每份一次 |
| 发布问卷 | -10 | 需积分 ≥10 |
| 未答完（>20%） | 0 | 不发积分 |
| 质量无效/逾期 | 0 | 不发积分 |

**信誉（credit，0–100）**

| 行为 | 变动 | 说明 |
|---|---|---|
| 初始 | 0 | 新用户 |
| 新人任务（阅读规则） | +40 | 一次性，+0 积分 |
| 有效完成问卷 | +5 | 每份一次 |
| 未答完（>20%） | -5 | 每份一次 |
| 逾期未提交 | -20 | 每份一次，不扣积分 |
| 发布 | 0 | 只校验 ≥40，不扣信誉 |

**等级**

| 分数 | 等级 |
|---|---|
| 85–100 | 优秀 |
| 70–84 | 良好 |
| 40–69 | 一般 |
| 0–39 | 较差 |

**流水**

- 每条：时间、变动值、原因、关联问卷、变动后余额；
- 积分与信誉分开展示；
- 只追加，不修改历史；
- 用户可查最近 60 条，P1 支持分页。

### 6.7 个人中心（P0）

- 昵称编辑（默认校园用户，2–20 字）；
- 积分/信誉双卡 + 等级；
- 信誉分记录、积分记录（独立卡片）；
- 我发布的问卷：数量、收到作答数；P1 查看统计；
- 我填写的问卷：问卷标题、获得积分、填写时间；点击“查看作答”进入只读详情，高亮原选项；
- 未答完/已过期记录：显示状态、未获得积分、信誉扣分，不可重答；
- 7 天隐私提示：填写记录按策略清理（仅清理展示记录，不影响已结算流水）。

### 6.8 统计与导出（P1）

- 发布者可见：回收份数、有效/无效/未答完数量、每题选项分布、开放题原文；
- 仅问卷所有者可见；
- 导出 CSV/JSON 由服务端生成，文件名含问卷 id；小程序用 `wx.openDocument` 打开；
- 导出内容不含学号、openid、手机号、IP。

## 7. 业务规则汇总

### 7.1 状态机

**问卷**：`open`（可作答）→ `closed`（截止/下架）。

**作答记录**：

| 状态 | 触发 | 用户可见 |
|---|---|---|
| `in_progress` | start | 作答中 |
| `valid` | 提交且有效 | 已完成，+5/+5 |
| `invalid` | flags ≥2 | 未通过质量核验，不可重答 |
| `incomplete` | 未答率 >20% | 未答完，-5 信誉，可查看，不可重答 |
| `expired` | 截止未提交/超时 | 已过期，-20 信誉，不可重答 |

### 7.2 防重复

- 唯一约束：`responses(survey_id, user_id)`；
- 提交幂等：`requestId` 唯一；
- 发布者自填：`survey.owner_id == user.id` 直接拒绝；
- 一学号一账号：`users.student_hash` 唯一。

### 7.3 时间

- 所有时间以服务端为准；
- 截止时间后：start 拒绝、submit 拒绝；
- attempt 过期由定时任务/惰性检查处理；
- 逾期扣分只执行一次。

## 8. 数据模型（MVP）

| 表 | 关键字段 |
|---|---|
| `users` | id, openid, student_hash, nickname, points, credit, onboarded, created_at |
| `surveys` | id, owner_id, title, category, minutes, start_at, end_at, status, created_at |
| `questions` | id, survey_id, type(single/multiple/open), title, sort |
| `options` | id, question_id, text, sort |
| `attempts` | id, survey_id, user_id, started_at, submitted_at, status, end_at |
| `responses` | id, survey_id, user_id, attempt_id, answers_json, flags_json, status, created_at；唯一(survey_id,user_id) |
| `point_ledger` | id, user_id, delta, reason, survey_id, balance_after, created_at |
| `credit_ledger` | id, user_id, delta, reason, survey_id, balance_after, created_at |

索引建议：`users(student_hash)` 唯一、`responses(survey_id,user_id)` 唯一、`surveys(status,end_at)`、`attempts(status,end_at)`、`*_ledger(user_id,created_at)`。

## 9. 接口契约（最小）

统一前缀 `/api`；返回 `{ code, message, data }`；错误 `code` 稳定，前端按 code 提示。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/login` | `{code, mockOpenid?}` → token、user、needBind |
| POST | `/auth/bind` | `{studentNo, nickname}` → user |
| GET | `/surveys?status=open` | 列表 |
| GET | `/surveys/{id}` | 详情 + 题目/选项 |
| POST | `/surveys` | 发布；`requestId` 幂等 |
| POST | `/surveys/{id}/start` | 创建 attempt，返回 `attemptId/startedAt` |
| POST | `/surveys/{id}/submit` | `{attemptId, answers, requestId}` → 结果 |
| GET | `/me` | 用户、积分、信誉、等级 |
| GET | `/me/ledger?type=points\|credit` | 双流水 |
| GET | `/me/surveys` | 我发布的 |
| GET | `/me/responses` | 我填写的 |
| GET | `/surveys/{id}/stats` | P1，仅所有者 |
| GET | `/surveys/{id}/export` | P1，CSV/JSON |

**关键错误码**

`AUTH_REQUIRED`、`STUDENT_ALREADY_BOUND`、`SURVEY_NOT_FOUND`、`SURVEY_CLOSED`、`SELF_ANSWER_FORBIDDEN`、`ALREADY_SUBMITTED`、`POINTS_NOT_ENOUGH`、`CREDIT_NOT_ENOUGH`、`ATTEMPT_EXPIRED`、`QUALITY_INVALID`、`INCOMPLETE`、`RATE_LIMITED`、`SERVER_ERROR`。

## 10. 非功能需求

### 10.1 安全与隐私

- 不采集真实姓名、手机号、IP；
- 学号仅存 HMAC，盐值服务端保存；
- JWT 有效期 7 天，敏感接口校验；
- 发布者不能查看填写者身份；
- 导出不包含 openid/学号哈希；
- 日志不记录明文答案中的敏感信息（P1 可加）。

### 10.2 性能

- 首屏 <2 秒（4G/校园网）；
- 核心接口 P95 <500ms（本地/局域网）；
- 列表默认 20 条，分页。

### 10.3 兼容

- 微信开发者工具 + iOS/Android 真机；
- 屏幕宽度 375–430px；
- 不依赖第三方 UI 框架，原生 WXML/WXSS/JS。

## 11. 验收标准

| ID | Given / When / Then |
|---|---|
| AC-01 | 新用户未绑定学号，进入首页被引导绑定；绑定后积分 0、信誉 0 |
| AC-02 | 信誉 0、积分 0 时点发布，提示信誉不足，不能提交 |
| AC-03 | 领新人任务后信誉 40、积分 0，仍因积分不足不能发布 |
| AC-04 | 完成 2 份问卷后积分 10、信誉 50，可发布；发布后积分 0 |
| AC-05 | 同一问卷重复提交，第二次返回第一次结果，积分/信誉不重复增加 |
| AC-06 | 发布者打开自己的问卷，不能作答，只能看统计/管理 |
| AC-07 | 4 题只答 3 题（25%），提交后为未答完：0 积分、信誉 -5、不可重答 |
| AC-08 | 4 题全答但 2 秒提交，判 fast；若再命中直线，flags≥2 判无效，0 分 |
| AC-09 | 4 题全选同一项，判 straight；结合 fast 判无效 |
| AC-10 | 开放题只填“1”，判 open_invalid；与 fast 组合判无效 |
| AC-11 | 截止后提交被拒绝；逾期 attempt 扣 20 信誉且只扣一次 |
| AC-12 | 个人中心能看到积分/信誉流水的时间、原因、余额；填写记录可查看原选项 |
| AC-13 | 未绑定用户不能调用发布/提交接口；越权访问他人统计返回 403 |
| AC-14 | 连续 10 次执行主流程，无崩溃、无重复加分、无半份问卷 |

## 13. 风险与开放问题

### 13.1 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 小程序 HTTPS/域名/AppID 未就绪 | 真机无法请求 | 开发工具勾“不校验合法域名”；15 号前准备云托管/局域网；登录留 mock 开关 |
| 服务端计时/判重被绕过 | 刷分 | 时间、attempt、唯一索引全在服务端；前端只展示 |
| 质量规则误杀 | 用户申诉 | 阈值固定可解释；P1 用真实数据校准；保留 flags 明细 |
| 三人时间被课程/备赛切碎 | 联调延期 | 14 号 Mock 闭环、15 号真机走通、17 号冻结；P1 可砍 |
| 编辑问卷破坏历史答案 | 统计错位 | MVP 发布后禁止改题；P1 用版本号/快照 |
| 跨设备一人一卷 | 无法绝对保证 | 只承诺 HMAC + 唯一索引，不宣称绝对 |

### 13.2 开放问题

1. 是否做 60 人小试？——MVP 先做 5–10 人功能自测，不编造数据。
2. 导出格式 CSV 还是 XLSX？——服务端 CSV，小程序 `openDocument`；P1 再定。
3. 填写记录保留多久？——展示记录 7 天清理；流水永久保留（演示期）。
4. 是否允许发布后编辑？——MVP 不允许；P1 用版本化。
5. 是否需要举报/下架？——P1；MVP 由发布者删除自己的问卷（无答卷时）。
