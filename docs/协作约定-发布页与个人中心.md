# 协作约定：发布页 & 个人中心

> 版本：v1.0（2026-11-09）
> 适用：校园问卷互助积分平台 Web MVP（原生 HTML + 原生 JS + Bootstrap 5 CDN）
> 维护：首页 / 积分逻辑负责人 & 发布页负责人 & 个人中心负责人

---

## 0. 一句话原则

**数据只有一份，入口只有一个：`window.SurveyStore`。**
页面只负责“收集输入”和“渲染结果”，不直接读写 `localStorage` 里的业务数据。

---

## 1. 文件与职责边界

| 文件 | 负责人 | 说明 |
|---|---|---|
| `index.html` | 首页 / 积分 | 问卷列表容器 `#question-list`，由 `app.js` 渲染 |
| `detail.html` | 首页 / 积分 | 答题、领取积分、防重复 |
| `js/app.js` | 首页 / 积分 | **唯一数据层**：积分、领取记录、问卷存储、校验、渲染 |
| `publish.html` | 发布页同学 | 只做表单收集，提交时调用 `SurveyStore.create()` |
| `profile.html` | 个人中心同学 | 只做展示，读 `points` 与 `SurveyStore` 接口 |
| `css/style.css` | 公共 | 改样式不影响结构的前提下自由修改 |

约定：

1. 不要修改 `js/app.js` 里的存储 key、奖励/成本常量、校验规则；需要改先在本群说明，双方确认后同步更新本文档。
2. 不要修改其他人的 HTML 结构；只加自己页面需要的事件与容器。
3. 新增页面能力优先走 `SurveyStore`，不要在页面里再写一套读写逻辑。

---

## 2. localStorage：三个 key，各管各的

| key | 内容 | 谁写 | 页面能否直接写 |
|---|---|---|---|
| `points` | 当前积分，字符串数字，初始 `"50"` | `app.js` | **不能** |
| `claimed` | 已领取的问卷 id 数组，如 `["1","u..."]` | `app.js` | **不能** |
| `surveys` | 用户发布的问卷数组（JSON） | `app.js` | **不能** |

- 页面可以 **读** `points` 用于展示，但加减分必须由 `app.js` 完成。
- `surveys` 的结构由 `app.js` 统一清洗，页面自己塞数据会被首页过滤掉。
- 手动改浏览器 DevTools 里的值只影响本机演示，不作为联调依据。

---

## 3. 唯一接口：`window.SurveyStore`

`app.js` 加载后挂到 `window` 上，所有页面可直接用。

| 方法 | 签名 | 返回 | 用途 |
|---|---|---|---|
| `create` | `create(payload)` | 成功 `{ ok:true, id, points }`；失败 `{ ok:false, error, code? }` | 发布问卷（含校验、扣 10 分、落库） |
| `remove` | `remove(id)` | `true / false` | 删除自己发布的问卷 |
| `get` | `get(id)` | `survey / null` | 按 id 取问卷（内置 + 用户发布） |
| `list` | `list()` | `survey[]` | 全部问卷，用户发布的在前 |
| `mine` | `mine()` | `survey[]` | 我发布的问卷 |
| `history` | `history()` | `[{ id, title, reward, exists }]` | 我填写过的问卷（按领取顺序） |
| `categories` | 属性 | `["学习","生活","调研","其他"]` | 发布页分类下拉 |
| `reward` | 属性 | `5` | 填写一份奖励 |
| `publishCost` | 属性 | `10` | 发布一份消耗 |

> 常量只读，不要在页面里写死 `5` / `10`，统一用 `SurveyStore.reward`、`SurveyStore.publishCost`，以后调价只改一处。

---

## 4. 问卷数据结构

```js
{
  id: "u1731052800000ab3",   // 由 create() 生成，页面不要自己造
  title: "图书馆座位使用情况调查",
  publisher: "我",
  category: "学习",           // 必须是 categories 里的值，否则归为“其他”
  minutes: 2,                // 1–60，缺省 3
  reward: 5,                 // 固定，create() 会忽略调用方传的值
  createdAt: 1731052800000,  // 时间戳
  mine: true,                // 用户发布固定 true，内置为 false
  questions: [
    { q: "你每周去图书馆几次？", options: ["1-2 次", "3-5 次", "6 次以上"] }
  ]
}
```

校验规则（由 `create()` 统一执行，发布页可以提前做同样的提示）：

| 字段 | 规则 | 失败提示示例 |
|---|---|---|
| `title` | 必填，≤ 40 字 | `请填写问卷标题` / `标题最多 40 个字` |
| `questions` | 1–10 题 | `至少需要 1 道题目` / `最多支持 10 道题` |
| `q` | 每题必填，≤ 100 字 | `第 2 题的题目不能为空` |
| `options` | 每题 2–6 个，去空行，不能重复，每个 ≤ 50 字 | `第 2 题至少需要 2 个选项` |
| 积分 | ≥ `publishCost`（10） | `积分不足，发布需要 10 分，当前只有 5 分`（`code: "POINTS_NOT_ENOUGH"`） |
| 存储 | 写入成功 | `本地存储不可用，问卷没有保存，请检查浏览器设置`（`code: "STORAGE_ERROR"`，不会扣分、不会留下半份问卷） |

## 5. 发布页接入方式

### 5.1 页面要求

- 顶部导航显示当前积分；底部导航保持“首页 / 发布问卷 / 我的”。
- 表单至少包含：标题、题目、选项；题目/选项支持动态增删（原生 JS）。
- 提交按钮文案：**“消耗 10 积分发布问卷”**（用 `SurveyStore.publishCost` 拼）。
- 可选体验：积分 < 10 时按钮置灰并提示“积分不足”，但**不能只靠前端禁用**，`create()` 会再校验一次。

### 5.2 提交代码

```js
document.getElementById('publish-form').addEventListener('submit', function (e) {
  e.preventDefault();

  // 从你的表单里收集，格式必须是 [{ q, options: [...] }]
  var questions = collectQuestions();

  var res = window.SurveyStore.create({
    title: document.getElementById('title').value,
    publisher: '我',                 // 可省略
    category: document.getElementById('category').value, // 可省略
    minutes: 3,                      // 可省略
    questions: questions
  });

  if (!res.ok) {
    alert(res.error);                // 直接展示，不要自己拼错误文案
    return;
  }

  alert('发布成功，消耗 10 积分，当前剩余 ' + res.points + ' 分');
  location.href = 'detail.html?id=' + encodeURIComponent(res.id);
  // 或者回首页：location.href = 'index.html';
});
```

### 5.3 发布页禁止事项

- **不要**自己 `localStorage.setItem('surveys', ...)`。
- **不要**自己从积分里减 10；`create()` 内部已经扣了，否则会扣两次。
- **不要**自己生成 id；内置问卷是 `"1"` / `"2"`，用户问卷统一 `u` 开头。
- **不要**在 `create()` 之外再写一份“发布成功但没落库”的逻辑。

## 6. 个人中心接入方式

### 6.1 积分展示

```html
<h1 id="profile-points">50</h1>
```

`app.js` 已经会自动更新 `#profile-points` 和顶栏 `#top-points`，页面不需要再写读取逻辑。
如需额外位置，加 `data-points` 属性即可自动同步。

### 6.2 我发布的问卷

```js
var list = window.SurveyStore.mine();
var box = document.getElementById('my-surveys');

if (list.length === 0) {
  box.innerHTML = '<p class="text-muted">还没有发布过问卷</p>';
} else {
  box.innerHTML = '';
  list.forEach(function (s) {
    var row = document.createElement('div');
    row.className = 'd-flex justify-content-between align-items-center border-bottom py-2';

    var title = document.createElement('span');
    title.textContent = s.title;          // 必须 textContent，防 XSS

    var right = document.createElement('span');
    var link = document.createElement('a');
    link.href = 'detail.html?id=' + encodeURIComponent(s.id);
    link.textContent = '查看';
    link.className = 'me-3';

    var del = document.createElement('button');
    del.className = 'btn btn-sm btn-outline-danger';
    del.textContent = '删除';
    del.onclick = function () {
      if (!confirm('确定删除《' + s.title + '》吗？')) return;
      if (window.SurveyStore.remove(s.id)) row.remove();
    };

    right.appendChild(link);
    right.appendChild(del);
    row.appendChild(title);
    row.appendChild(right);
    box.appendChild(row);
  });
}
```

### 6.3 我填写过的问卷

`claimed` 里只有 id，页面不要自己拼标题，用 `history()`：

```js
window.SurveyStore.history().forEach(function (item) {
  // item = { id, title, reward, exists }
  // exists=false 表示问卷已被发布者删除，标题显示“问卷已删除”
});
```

注意：

- `history()` 按领取先后排序，**目前没有领取时间字段**；需要显示时间要先扩展数据结构，双方确认后再加。
- 自己发布的问卷也可以自己填写领积分，`claimed` 不区分发布者。

### 6.4 个人中心禁止事项

- **不要**直接写 `points` / `claimed` / `surveys`。
- **不要**自己解析 `claimed` 里的 id 去猜标题，用 `SurveyStore.get(id)` 或 `history()`。
- **不要**把删除做成“只删页面行不删存储”。

## 7. 视觉与交互约定

- 首页卡片统一由 `app.js` 渲染，结构是 `<a href="detail.html?id=...">`；个人中心不要在首页再插卡片。
- 已领取状态由 `app.js` 统一置灰（`btn-secondary` + `已完成填写` + 移除 href），页面不要手写灰色按钮。
- 发布页、个人中心沿用 Bootstrap 5 类名，不引入新框架、不引入构建工具。
- 移动端按 500px 宽度自测：顶部导航不换行、底部导航不遮挡内容（页面底部需 `pb-5`）。
- 提示文案统一用中文全角标点；金额/分数直接拼数字，不要写死“5 分”“10 分”。

---

## 8. 同步机制（已内置，不要重复实现）

| 场景 | 机制 |
|---|---|
| 发布页提交后回首页 | 首页重新加载时读取最新 `surveys` |
| 另一个标签页发布/领取 | `app.js` 监听 `storage`，自动重渲染列表与积分 |
| 浏览器前进/后退回首页 | `app.js` 监听 `pageshow`，重新同步 |
| 同一页面内发布 | `create()` 内部已调用一次列表渲染 |

页面不要自己再绑 `storage` / `pageshow` 做同样的刷新。

---

## 9. 安全与容错

1. **所有用户输入渲染前必须转义**：优先 `textContent`；必须用 `innerHTML` 时先替换 `& < > " '`。
2. `app.js` 已对 `points` / `claimed` / `surveys` 做 `try/catch`，脏数据不会让页面白屏；页面不要假设数据一定合法。
3. 详情页无效 id 会显示“问卷不存在”，按钮为“问卷不可用”，`claimPoints()` 返回 `false`。
4. 存储写入失败（隐私模式/配额满）时 `app.js` 静默降级，页面不要因此报错阻塞渲染。

## 10. 联调验收清单

发布页：

- [ ] 未登录/首次进入，顶栏显示 50 分。
- [ ] 正常发布：首页第一张出现新问卷，带“我发布的”，积分 50 → 40。
- [ ] `detail.html?id=新id` 能打开，题目/选项与填写一致。
- [ ] 答完所有题才能领取，领取后 +5，按钮变“已完成填写”。
- [ ] 重复领取不加分；刷新后仍然置灰。
- [ ] 积分 < 10 时发布被拒，提示“积分不足”，积分与问卷数量都不变。
- [ ] 标题里写 `<b>x</b>` 只显示文本，不生成 HTML。
- [ ] 必填/选项数量/重复选项校验都有提示。

个人中心：

- [ ] 大数字与顶栏积分一致；领取后刷新仍一致。
- [ ] “我发布的”只显示自己发布的，删除后首页同步消失。
- [ ] “我填写过的”显示标题而不是 id；问卷被删后显示“问卷已删除”。
- [ ] 空列表有兜底文案，不出现 `undefined`。

## 11. 变更流程

1. 要改接口、存储 key、奖励/成本、数据结构：先在群里说明，首页/积分负责人改 `app.js` 并更新本文档版本号。
2. 只改自己页面的展示：直接改，不需要动 `app.js`。
3. 合并前各自跑一遍第 10 节清单；涉及公共逻辑的改动由首页/积分负责人补测。
4. 提交信息统一用半角冒号：`feat: ...` / `fix: ...` / `docs: ...`。
