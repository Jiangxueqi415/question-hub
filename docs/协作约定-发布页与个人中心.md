# 协作约定：发布页、答题页与个人中心

> 版本：v2.0（2026-11-11）
> 适用：`web-mvp/` 校园问卷互助 Web 原型（原生 HTML + 原生 JS + Bootstrap 5 CDN）
> 维护：首页 / 积分逻辑负责人、发布页负责人、个人中心负责人

---

## 0. 一句话原则

**数据只有一份，入口只有一个：`window.SurveyStore`。**

页面只负责“收集输入”和“渲染结果”，不直接读写 `localStorage` 里的业务数据。
当前版本仍是纯前端原型：身份、跨设备汇总、真实鉴权一律留到后端阶段，本机 `localStorage` 只用于演示。

---

## 1. 文件与职责边界

目录均相对 `web-mvp/`：

| 文件 | 职责 |
|---|---|
| `index.html` | 首页容器：双积分卡 `#score-cards`、问卷列表 `#question-list` |
| `detail.html` | 答题、截止时间校验、领取奖励 |
| `js/app.js` | **唯一数据层**：积分、信誉分、流水、问卷、作答记录、校验、详情渲染 |
| `publish.html` | 发布 / 编辑表单容器 |
| `js/publish.js` | 发布页表单收集、题目/选项动态增删、时间窗、提交锁；只调用 `SurveyStore` |
| `profile.html` | 个人中心：积分/信誉分、流水、发布统计、填写记录 |
| `js/profile.js` | 个人中心渲染；不直接写业务数据 |
| `js/stats.js` | 详情页与个人中心共用的统计条形图视图 |
| `css/style.css` | 公共样式 |

约定：

1. 存储 key、积分/信誉分常量、校验规则集中在 `js/app.js`，页面不要另存一份。
2. 页面渲染用户输入时优先 `textContent`；必须拼 HTML 时先转义。
3. 新增能力优先扩展 `SurveyStore`，不要在页面里重复读写 `localStorage`。

## 2. localStorage 与业务常量

| key | 内容 | 谁写 |
|---|---|---|
| `points` | 当前积分，字符串数字，初始 `"0"` | `app.js` |
| `credit` | 当前信誉分，`0–100`，初始 `"0"` | `app.js` |
| `claimed` | 已领取记录：`{ id, time, status?, reason? }[]`；超过 7 天由个人中心清理展示记录 | `app.js` / `profile.js` |
| `lockedClaims` | 7 天清理后保留的永久防重锁：`{ id, status }[]`，不在页面展示 | `app.js` |
| `surveys` | 用户发布的问卷数组（JSON） | `app.js` |
| `responses` | 作答记录：`{ surveyId, at, answers }[]` | `app.js` |
| `attempts` | 已开始未提交的作答：`{ surveyId, startedAt, endAt, penalized }[]` | `app.js` |
| `creditLog` | 信誉分流水，最多 60 条 | `app.js` |
| `pointsLog` | 积分流水，最多 60 条 | `app.js` |
| `onboarded` | 新人任务是否已领取，`"0"` / `"1"` | `app.js` |

关键常量：

- 初始积分 `0`，初始信誉分 `0`，信誉分上限 `100`。
- 新人任务：一次性 `+40 信誉分`，不加积分；首次发布仍需先完成他人问卷攒够 `10 积分`。
- 完成一份问卷：`+5 积分`、`+5 信誉分`；信誉分封顶 100，流水记录实际增加量。
- 发布一份问卷：`-10 积分`，且信誉分必须 `≥ 40`。
- 逾期未完成作答：`-20 信誉分`，不扣积分；信誉分最低为 0。

## 3. 唯一接口：`window.SurveyStore`

| 方法 / 属性 | 说明 |
|---|---|
| `create(payload)` | 发布；成功 `{ ok:true, id, points }`，失败 `{ ok:false, error, code? }` |
| `update(id, payload)` | 编辑已发布问卷；保存不扣积分 |
| `remove(id)` | 删除自己发布的问卷，同时清空该问卷作答与逾期记录 |
| `get(id)` | 按 id 取问卷（内置 + 用户发布） |
| `list()` | 全部问卷，用户发布的在前 |
| `mine()` | 我发布的问卷 |
| `history()` | 我填写过的问卷：`{ id, title, reward, exists, time }` |
| `stats(id)` | 作答统计：选择题人数/占比，开放题文字列表 |
| `getUser()` | `{ score, credit, level, onboarded }` |
| `getCredit()` | 当前信誉分 |
| `onboard()` | 领取新人任务 |
| `reward` / `creditReward` | 完成奖励 `5` / `5` |
| `publishCost` | 发布消耗 `10` |
| `creditMin` | 发布最低信誉分 `40` |
| `penaltyCredit` | 逾期扣分 `20` |
| `coverMaxLen` / `openAnswerMax` | 封面 data URL 上限 `450000` / 开放题字数 `100` |
| `points` / `credit` | 只读属性 |

> 页面不要写死 `5 / 10 / 40 / 20 / 100`，统一用上面的常量。

## 4. 数据结构

```js
{
  id: "u1731052800000ab3",
  title: "图书馆座位使用情况调查",
  publisher: "匿名同学",       // 发布页固定匿名，不采集真实姓名
  category: "学习",            // 学习 | 生活 | 调研 | 其他
  minutes: 2,                  // 1–60
  reward: 5,
  createdAt: 1731052800000,
  startAt: 1731052800000,      // 必填：开始作答时间戳
  endAt: 1731657600000,        // 必填：截至作答时间戳
  mine: true,
  locked: true,
  cover: "",                   // 可选：压缩后的图片 data URL
  questions: [
    {
      q: "你每周去图书馆几次？",
      type: "single",          // single | multiple | open
      options: ["1-2 次", "3-5 次", "6 次以上"] // open 题为 []
    }
  ]
}
```

作答记录：

```js
{
  surveyId: "u1731052800000ab3",
  at: 1731052800000,
  answers: [
    1,          // 单选：选项下标
    [0, 2],     // 多选：选项下标数组
    "我的看法"   // 开放题：文字，最多 100 字
  ]
}
```

逾期起点：

```js
{
  surveyId: "u1731052800000ab3",
  startedAt: 1731052800000,
  endAt: 1731657600000,
  penalized: false
}
```

> 只有用户在答题页实际选择 / 输入过答案，才写入 `attempts`；单纯浏览统计不会触发逾期扣分。
> 成功提交会删除对应 attempt；删除问卷会一并清空 responses / attempts。

## 5. 发布校验（`create()` / `update()` 统一执行）

| 项目 | 规则 | 提示 |
|---|---|---|
| 积分门槛 | 新建发布需 ≥ 10 | `您的积分不足，请去参与问答赚取积分` |
| 信誉分门槛 | 新建发布需 ≥ 40 | `信誉分不足` |
| 双门槛 | 两者都不足时按顺序拼接 | `您的积分不足，请去参与问答赚取积分；信誉分不足` |
| 标题 | 必填，≤ 40 字 | `请填写问卷标题` / `标题最多 40 个字` |
| 题目 | 1–10 题，每题 ≤ 100 字 | `至少需要 1 道题目` / `第 2 题的题目不能为空` |
| 选项 | 选择题 2–6 个、去空行、不重复、每个 ≤ 50 字 | `第 2 题至少需要 2 个选项` |
| 开放题 | `type: "open"`，不需要选项 | 不校验选项 |
| 时间窗 | `startAt` / `endAt` 必填；`endAt > startAt`；新建时 `endAt > 当前时间` | `请选择问答开始和截至日期` / `截至日期必须晚于开始日期` |
| 发布者 | 发布页固定 `匿名同学`，只读 | 不采集真实姓名 |
| 封面 | 原图 ≤ 2MB；压缩后 data URL ≤ `coverMaxLen` | `图片过大，请换一张或移除封面` |
| 正确答案 | **已移除**，问卷只收集作答信息 | 无 |
| 存储 | 任一写入失败整体回滚 | `本地存储不可用，问卷没有保存，请检查浏览器设置` |

> 发布页会在提交前先做同样的门槛提示；`create()` 仍会再校验一次，不能只靠按钮禁用。
> 信誉分当前按 0–100 封顶，写作“扣 20”时如果剩余不足 20，会扣到 0 为止。

## 6. 发布页要求

- 顶部显示当前积分；表单顶部显示当前信誉分与发布条件。
- 发布者固定为 `匿名同学` 且只读；标题 40 字（`maxlength`、计数、提示、数据层上限一致）。
- 开始 / 截至日期使用 `datetime-local`，默认开始为当前时间、截至为 7 天后。
- 题目支持单选 / 多选 / 开放题：
  - 选择题 2–6 个选项；
  - 开放题隐藏选项区，作答上限 100 字。
- 题目 placeholder 按分类给模板示例，如“学习”类显示“例如：你平时喜欢看什么书？”；输入内容后自然消失。
- 选项输入框不再放提示词；开放题答题框在详情页显示“请输入你的看法”。
- 不设置正确答案，不展示“参考答案”。
- 提交入口有 `submitting` 锁，按钮禁用；失败恢复、成功直接跳转，避免连点生成两份问卷。
- 发布按钮同时校验积分与信誉分，按未满足的条件分别显示：
  - 仅积分不足：`您的积分不足，请去参与问答赚取积分`
  - 仅信誉分不足：`信誉分不足`
  - 两者都不足：两条提示用“；”连接
- 监听 `storage` 的 `points` / `credit`，另一个标签页加减分后自动刷新按钮与提示。
- 封面压缩完成后立即检查长度，超限提示，不静默丢弃。
- 编辑模式保存不扣积分，字段与时间窗正常回填。

## 7. 答题页与统计

- 进入有截止时间的问卷时显示：
  **“请注意在截至日期内完成作答，否则视为无效”**，并展示开始 / 截至时间。
- 未开始：输入框禁用，按钮“问答尚未开始，暂不可作答”。
- 已截止：输入框禁用，按钮“问答已截止，作答无效”；提交入口也会拒绝。
- 开放题：textarea 占位“请输入你的看法”，超过 100 字立即截断并提示“仅可输入100字”，右下角显示字数。
- 完成全部题目后才能提交；提交成功后 `+5 积分`、`+5 信誉分`，并写入 `responses`。
- 统计只对 `survey.mine === true` 的发布者视图渲染；作答者与内置问卷不显示统计。
- 统计展示：
  - 选择题：每个选项下方一条浅色横条，末尾显示“N 人 · P%”，占比按该题作答人数计算；
  - 开放题：发布者可见文字作答列表，显示“共 N 条”。
  - 详情页与个人中心共用 `js/stats.js` 和同一套 CSS，颜色为浅蓝 `#b9d4f6`。

### 7.1 逾期扣分

- 用户在答题页实际选择 / 输入答案时，记录一条 `attempts`。
- 以下时机结算逾期：页面初始化、`pageshow`、提交时发现已截止。
- 结算规则：`attempt.endAt`（或问卷当前 `endAt`）已过且未领取 → 扣 20 信誉分，不扣积分，写入信誉分流水。
- 每条 attempt 只扣一次（`penalized: true`）；成功领取、删除问卷会清除。
- 扣分后页面顶部显示浮层提示；信誉分最低 0。

## 8. 个人中心要求

- 顶部展示当前积分；页面内展示积分、信誉分、信誉等级和进度条。
- 保留新人任务按钮与积分 / 信誉分流水；演示扣分按钮仅在 `profile.html?demo=1` 时显示。
- “我发布的问卷”：
  - 每份问卷显示标题、分类、截止时间、状态（进行中 / 未开始 / 已截止）、收到作答数；
  - “查看统计”展开与详情页相同的条状图和开放题作答；
  - 提供打开、编辑、删除；删除后统计、作答、逾期记录一并清空。
- “我填写过的问卷”：
  - 显示标题、获得积分、填写时间（来自 `responses.at`）；
  - 问卷已删除时显示“问卷已删除”。
  - 填写记录展示保留 7 天；超期清理前先把 `{id,status}` 写入 `lockedClaims`，保证清理后仍不能重复领取。
- 所有动态标题用 `textContent`，统计文本用 `stats.js` 转义，禁止把 `item.title` 直接拼进 `innerHTML`。
- 监听 `surveys / claimed / lockedClaims / responses / attempts / points / credit` 的 `storage` 事件，多标签页同步。

## 9. 同步机制

| 场景 | 机制 |
|---|---|
| 发布后回首页 | 页面重新加载读取最新 `surveys` |
| 另一个标签页发布 / 作答 / 删除 | `app.js` 与 `profile.js` 监听 `storage` |
| 另一个标签页加减积分 / 信誉分 | 发布页监听 `points` / `credit`，刷新门槛提示 |
| 浏览器前进 / 后退 | `app.js` 监听 `pageshow`，重新同步并补算逾期 |
| 同一页面内发布 | `create()` 内部刷新列表与积分 |

页面不要重复实现整页刷新；只监听自己需要的最小 key。

## 10. 安全与容错

1. 用户输入渲染前必须转义：优先 `textContent`；必须 `innerHTML` 时替换 `& < > " '`。
2. `app.js` 对 points / credit / claimed / surveys / responses / attempts / 流水都做 `try/catch`，脏数据不会白屏。
3. 领取 / 发布 / 逾期扣分涉及的多处写入必须检查成功；失败要回滚，避免“加分了但没记录”或“没扣分却发布成功”。
4. 详情页无效 id 显示“问卷不存在”，按钮“问卷不可用”。
5. 纯前端无法真正鉴权：`survey.mine` 仍可被 DevTools 伪造，演示口径不宣称“只有发布者能改”。

## 11. 联调验收清单

发布页：

- [ ] 首次进入积分 0、信誉分 0，发布按钮禁用，提示“您的积分不足，请去参与问答赚取积分；信誉分不足”。
- [ ] 完成新人任务后积分仍为 0、信誉分 40，发布按钮仍禁用（还差 10 积分）。
- [ ] 正常发布后积分 -10，首页第一张出现新问卷。
- [ ] 仅积分不足 / 仅信誉分不足时分别出现对应提示。
- [ ] 连点提交只生成一份问卷、只扣一次 10 分。
- [ ] 标题 40 字；发布者固定“匿名同学”；选项输入框无提示词。
- [ ] 开始 / 截至日期缺失、截至早于开始、截至早于当前时间都有提示。
- [ ] 开放题可发布；选择题选项 2–6 个校验正常。
- [ ] 封面超限提示“图片过大，请换一张或移除封面”。

答题页：

- [ ] 顶部显示“请注意在截至日期内完成作答，否则视为无效”。
- [ ] 未开始 / 已截止时输入框禁用，按钮不可用。
- [ ] 答完所有题才能提交；提交后 +5 积分、+5 信誉分。
- [ ] 开放题超过 100 字截断并提示“仅可输入100字”。
- [ ] 发布者选项下方出现浅色统计条；作答者不显示统计。
- [ ] 开始作答后逾期未提交，刷新页面扣 20 信誉分、积分不变，且只扣一次。

个人中心：

- [ ] 积分 / 信誉分 / 等级 / 进度条与流水一致。
- [ ] “我发布的问卷”可展开统计条形图与开放题作答。
- [ ] “我填写过的问卷”显示标题、获得积分、填写时间。
- [ ] 删除问卷后列表、统计、作答记录同步清理。
- [ ] 多标签页发布 / 作答后列表自动刷新。
